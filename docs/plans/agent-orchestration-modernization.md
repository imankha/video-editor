# Agent Orchestration Modernization

## Constraints

- Keep `scripts/task.sh drive` and Claude Code CLI as the model boundary so worker usage stays
  on the Claude subscription.
- Keep repository knowledge docs and registered agents as the worker instruction layer.
- Add orchestration incrementally around the current workflow; do not rewrite working agents.
- Treat `CLAUDE.md` as the policy source, structured run state as the operational source, and
  emitted events as the audit source.

## First group: consistent instructions and trustworthy evidence

This is the immediate rollout group. It preserves the existing CLI/subscription boundary,
isolated workers, domain knowledge, tiered implementation, curated local checks, and full
affected-layer CI. A separate proof gate applies before automatic landing at every tier.
The user requires compelling proof: write failing tests first whenever possible; later tests
carry the same burden of proving failure before and success after. Unproven docs/refactors
do not receive an implicit automatic-merge exemption.

Instructions are not mechanical enforcement. The status column distinguishes this completed
instruction pass from CI, archive, and toolchain work still to implement. No new orchestration
framework or database is required for this group.

## Later roadmap (proposal, not first-group commitments)

| Step | Capability | Benefit | Implementation details | Completion evidence |
|---:|---|---|---|---|
| 1 | Instruction conformance gate | Prevents old agent names, unbounded write agents, retired statuses, and contradictory mechanics from returning. | Run `python scripts/audit-agent-instructions.py` locally and in Branch CI whenever `CLAUDE.md`, `.claude/**`, or the audit script changes. Extend checks only for machine-verifiable invariants; keep policy prose centralized in `CLAUDE.md`. | Audit exits zero on the current tree and fails against a fixture containing a legacy invocation. |
| 2 | Define the run-state schema | Gives every task and wave one explicit vocabulary before persistence code is added. | Create versioned Pydantic/dataclass models for `Run`, `TaskRun`, `StageAttempt`, `Gate`, `Artifact`, `ReviewFinding`, and `Evidence`. Include IDs, schema version, timestamps, task/branch/commit, worker/session/container, tier, stage, status, attempt, dependencies, input/output artifact paths, and error classification. Use enums matching `TODO/WIP/WAITING_ON_USER/STAGING/DONE` and worker terminal states `PUSHREADY/BLOCKED/FAILED`. | Schema round-trip test plus rejection tests for illegal status/stage transitions. |
| 3 | Choose SQLite as the durable store | Replaces the partially structured `WAVE.md` and append-only status files with atomic, queryable state while remaining local and dependency-light. | Add `C:/work/tasks/orchestrator.db` with WAL mode, foreign keys, migrations, and tables corresponding to the schema. Store large prompts/logs as files and record paths plus SHA-256 hashes. Keep run IDs stable across supervisor restarts. | Kill/restart test reconstructs an in-flight wave without reading conversation history. |
| 4 | Add an event journal | Preserves causality and enables tracing, replay, and debugging without making mutable rows the only record. | In the same transaction as each state change, append an immutable event with `event_id`, `run_id`, `task_run_id`, `attempt_id`, monotonic sequence, UTC time, event type, actor, payload JSON, and correlation/parent IDs. Events include dispatch, stage start/end, tool result, gate opened/resolved, review finding, retry, push, CI verdict, and merge. | Replaying events produces the same current state as the materialized tables. |
| 5 | Wrap the existing worker launcher | Introduces durable orchestration without changing Claude behavior or billing. | Implement a `ClaudeCodeWorker` adapter that invokes `bash scripts/task.sh drive <slug> ...`, captures exit code and bounded stdout/stderr, records session/branch/commit, and never imports `ChatAnthropic` or accepts API credentials. Preserve the existing credential reseed and auth probe. | One existing task can run through the adapter with the same CLI output and subscription authentication. |
| 6 | Replace status-file parsing with structured worker events | Removes ambiguous free-text completion and silent worker death. | Give each worker a per-run event command or JSONL file contract. Require stage events with schema version and idempotency key. During transition, parse `.dotask-status` into the new schema and write both formats; make the database authoritative only after parity is proven. | Dual-write comparison shows no missing or reordered terminal/stage events across several tasks. |
| 7 | Add an idempotent transition service | Prevents double dispatch, duplicate merges, and corrupt retries after restarts. | Route all mutations through compare-and-set transitions. Encode allowed transitions, expected prior version, idempotency key, and side-effect state (`requested`, `started`, `succeeded`, `failed`). Claim work with a lease and heartbeat so only one supervisor owns an attempt. | Repeating the same dispatch, push, or merge request produces one side effect and one terminal result. |
| 8 | Add checkpoint and resume semantics | Lets a fresh supervisor continue from the last proven stage instead of rediscovering work or paying the context tax. | Checkpoint after classification, design approval, test creation, implementation, review resolution, QA, push, CI, and landing. Store artifact hashes and the Claude session ID when reusable. On resume, verify checkout HEAD and artifact hashes; use `-c` only when the session and checkout match, otherwise issue a fresh compact kickoff from state. | Supervisor restart at each stage resumes at the next incomplete transition without repeating completed side effects. |
| 9 | Add deterministic scheduling | Enforces WIP, dependencies, and file ownership mechanically. | Model the workflow as a LangGraph `StateGraph` or a small explicit state machine. Scheduler nodes contain no LLM call: select ready tasks, enforce WIP 4, serialize container startup, reject overlapping ownership sets, and release slots only at the configured bank point. Worker nodes call the existing adapter. | Simulation proves conflicting tasks never overlap and queued work starts after its dependency/bank condition. |
| 10 | Normalize review input | Gives reviewers complete, reproducible context and reduces prompt drift. | Build a review bundle from task acceptance criteria, approved design, base/head SHAs, diff path, changed-file list, relevant knowledge docs, test evidence, and unresolved risks. Hash the bundle. Reviewers receive paths and commit IDs rather than pasted summaries. | Two reviewers launched from the same bundle see identical inputs and the bundle remains inspectable later. |
| 11 | Persist structured findings | Turns review comments into resolvable workflow objects instead of prose lost between agents. | Require finding fields: stable ID, lens, severity, file/line, claim, evidence, violated invariant, recommended correction, status, implementor response, reviewer verdict, and resolution commit. Deduplicate by normalized location/invariant while retaining provenance. | Every major finding ends in `fixed`, `accepted-risk`, or `invalid`, with evidence and a resolution commit where applicable. |
| 12 | Implement the review loop | Makes correction and pushback repeatable while bounding cost. | For M tasks run one fresh reviewer; for L tasks fan out the configured lenses in parallel. Aggregate/dedupe findings, send accepted items to the original implementor session, return pushback to a fresh reviewer, and repeat until no unresolved major findings. Cap iterations and escalate a non-converging loop to `BLOCKED` with the disputed facts. | Seeded defect test produces a finding, correction, targeted re-test, reviewer closure, and preserved history. |
| 13 | Add verification and landing gates | Ensures review approval alone cannot ship unproven work. | Gate landing on resolved major findings, named relevant tests, acceptance-criterion evidence, clean diff, and green Branch CI. Automatic merge additionally requires the independent proof verdict and exact-revision evidence required by CLAUDE.md Landing Policy. Human-only cases open a `WAITING_ON_USER` gate with exact steps. | Attempts to land with missing evidence fail with a precise list; proven fixes follow the automatic path. |
| 14 | Instrument traces and spans | Shows where time, failures, retries, and subscription capacity are spent. | Emit OpenTelemetry spans for run, task, stage, worker dispatch, Claude turn, tool command, review, test, CI wait, and merge. Propagate `trace_id/run_id/task_run_id/attempt_id`. Record duration, model, exit status, token/usage fields when exposed, cache/session reuse, artifact hashes, and error class; never record credentials or full sensitive prompts by default. | A local trace reconstructs one task end to end and links every failure to its logs and state event. |
| 15 | Add local observability views | Makes the new state useful during ordinary supervision without requiring LangSmith. | Export OTLP to a local OpenTelemetry Collector with Jaeger/Tempo for traces and structured JSON logs. Add CLI commands for `status`, `timeline`, `blocked`, `review-findings`, `resume`, and `cost/usage`. Keep LangSmith optional for later evaluation work. | A fresh session can identify the critical path, current blockers, retry count, and last worker activity from one command/dashboard. |
| 16 | Add metrics and alerts | Detects silent stalls and systemic waste early. | Derive counters/histograms for stage latency, time-to-first-event, worker silence, retries, auth failures, quota stops, review iterations, CI failures, red-to-green proof rate, auto-merge rate, and tasks completed per subscription window. Alert on expired leases, no events within a stage threshold, repeated auth failure, and review-loop exhaustion. | Forced worker death and auth failure create actionable alerts tied to the correct run. |
| 17 | Add evals for agent instructions and reviews | Measures whether prompt changes improve outcomes rather than relying on intuition. | Build a small versioned corpus of past bugs/tasks with expected classification, required knowledge docs, critical review findings, test scope, and landing decision. Run agents against fixed commit snapshots. Track defect recall, false-positive severity, token use, latency, and retry rate. | Baseline report exists; an instruction change must not regress critical-finding recall or lifecycle correctness. |
| 18 | Migrate and remove compatibility state | Eliminates split-brain only after the durable path has proven itself. | Import active `WAVE.md` rows and `.dotask-status` histories, dual-read during a short soak, compare state continuously, then switch the UI and supervisor to SQLite. Retain a generated human-readable snapshot for inspection; stop accepting it as writable state. Back up and version the database migration path. | Multi-task soak completes with parity; recovery drill succeeds after deleting all generated snapshots. |

## Later-roadmap delivery slices

1. **Durable-state foundation (after the first group):** later-roadmap steps 1–4.
2. **Durable execution:** steps 5–9.
3. **Review and landing:** steps 10–13.
4. **Tracing and operations:** steps 14–16.
5. **Continuous improvement and cutover:** steps 17–18.

Each slice should land independently. LangGraph becomes useful at step 9; adopting it before
the state, events, and transition rules exist would move the current ambiguity into a graph
rather than remove it.
