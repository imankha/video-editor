passive effect (DefaultLane) while the accompanying seek writes zustand through `useVideo`'s

T10760.

## Traps that cost real time in the originating session

1. **Vacuous tests — this happened TWICE.** Both times a test passed for the wrong reason:
   - an e2e spec asserted "no 404s" while making **zero** requests;
   - a call-count test asserted "fires once" but `rerender()` with stable props never re-ran the
     effect, so it passed even against a retry that never disarms.
   **Always prove red**, and prefer a negative control in the same file (a case that must FAIL if
   the harness is inert).
2. **`page.evaluate(() => import('/src/stores/...'))` returns a DIFFERENT module instance** than the
   running app once Vite has HMR'd. Seeded or inspected state is a phantom. Tell-tale:
   `projects.length === 0` while the UI shows projects. Drive with clicks; observe DOM/network/console.
3. **"Maximum update depth exceeded" names the wrong culprit.** Its branch is
   `nestedPassiveUpdateCount > 50`, blamed on whatever setState comes next. The first capture in
   T10750 pointed at `setIsSeeking`, which was entirely innocent. Do not chase the callee it names.
4. **Verify the dev server serves your code** before trusting any live result — `curl` the module
   through Vite and grep for your change. A stale worker has produced false "still broken" verdicts
   in this repo before.
5. **Shared checkout.** Another session may be using the working tree. Commit early, stage explicit
   paths, never `git add -A`, never `git stash`.
