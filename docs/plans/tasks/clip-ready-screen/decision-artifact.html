The player already knows whether it is playing; it just never shows it. So: a 64px center glyph inside the video area, visible while paused and fading 600ms after play starts. It ignores pointer events, so the existing tap zones and the scrubber keep working. Play/Pause and Fullscreen icons join the header cluster next to Close, same ghost style as the other header icons, 44px touch floor on phones.

Fullscreen means "hide the footer and let the clip fill the panel". That is a CSS expand that works everywhere, with the browser's native fullscreen layered on where it exists. iPhone has no page fullscreen, so there the video opens in Apple's native player and comes back on dismiss. Escape leaves fullscreen first and closes the player only on a second press.

Rejected: the browser's native controls (they fight the tap zones and duplicate the scrubber on iOS) and a control strip under the video (steals about 44px from a portrait clip that is already short on height). Time readout not added; the scrubber already carries progress.

All of this is opt-in per caller. The other six screens that use this player are byte-identical until someone turns it on. The public share viewer is the obvious next place to turn it on.

Why this keeps the T9870 promise: the screen now contains no "Save" verb at all and says "Saved" once, so nobody can believe unsaved work is at risk. The "only you can see it" fact moves to the one place it matters, the Publish caption, which is where T9590 wanted the audience stated before the tap. Already-published re-exports still never get told "only you can see it".

The 22-kids sentence is not deleted; it stays as the Spotlight stage reason inside the editor. It was three lines in a 243px card, which is what made the cards feel like reading homework.

The Overlay stage completion gets the same treatment with Publish as the primary tile, so both bars stay one system as T9590 required.

What you are deciding, and what it touches

One decision: V1, V2 or V3, with the video controls and copy applying to all three. Deviations from earlier decisions, stated so you can veto them:

  • T9590 said the quiet exit "states its destination". "Done for now" does not. The landing toast still names Clips or Reels. Alternative if you want it: "Back to Clips" / "Back to Reels" computed from the project.
  • T9590 described the primary as a filled cyan button inside a tinted card. V2 and V3 drop the inner button; the tile itself carries the cyan weight. Dominance and order, which is what T9590 actually required, are unchanged.
  • The guided tutorial anchor on Publish moves from the inner button to the tile. Still exactly one element.

Size: Tier M. Frontend only. About 6 files (two action bars, CollectionPlayer, displayNames, two screens' player mounts) plus their unit tests and one e2e spec. No backend, no schema. Full proposal with exact Tailwind class strings per state is in docs/plans/tasks/post-export-ux-pass-proposal.md.
