## Scope as decided 2026-09-13: THE single copy and concept sweep

This task was imported as "apply one vocabulary and stable highlight identity". It is now the
**one copy pass across every screen**, and it **absorbs T9940**. The user's constraint is explicit:
*"I don't want too many UI iterations when I release, I just need to get it perfect now."* Six tasks
each editing their own corner is how the mixed vocabulary both evaluations found got there in the
first place.

**Reconcile against the 2026-09-10 shared-vocabulary epic before editing anything.** Five of its six
children (T9520-T9560) are already merged and shipped to production as of 2026-09-13. This task
refines that work; it must not undo it. `src/frontend/src/config/displayNames.js` remains the single
source, and the standing rule holds: **never rename internal APIs, routes, store keys, component
files or analytics vocabulary** to match UI text.

### 1. Vocabulary: Clip and Reel both stand

The intake proposed renaming Clip to Highlight (source N02/N06). **REJECTED.** A reel is a series of
clips, and "highlight" is a **modifier**, not a third object - everything the product makes is a
highlight. The 2026-09-10 object model (Game / Play / Clip / Reel / Published) is intact.

**Standing rule: short form in controls, long form in prose.**

- Tabs, buttons, chips, menus: **Clips**, **Reels**. Short, parallel, unambiguous in context.
- Explanatory copy, empty states, onboarding, marketing: **highlight clip**, **highlight reel**.
- **Never one sibling carrying the modifier while its sibling does not.** Today the `Clips` tab sits
  beside `SECTION_NAMES.LIBRARY = 'Highlight Reels'`, and `SECTION_NAMES.HIGHLIGHTS` is declared with
  the value `'Reels'`. That mismatch is the actual defect and it is small.

Also in scope from the original brief: kill `ModeSwitcher.jsx:94` "Select a reel first" (a dead end
that names the wrong object) in favour of naming the missing prerequisite precisely.

### 2. AI Focus becomes Framing

**The 2026-09-10 override is LIFTED.** That override's recorded reason in the shared-vocabulary
EPIC.md was that "AI Focus" should say *the reframing is automatic*. It is not: framing is the parent
placing crop keyframes, joined by an interpolated spline. There is no tracking in it.

- Mode noun: **Framing**. It has to work in a tab, a switcher and a status chip, so it must be a noun.
- Screen instruction: **"Frame your athlete"**. The intake proposed this as the mode name; it is a
  sentence, so it serves as the instruction instead.
- The app already says "Edit framing" in `FocusPublishActionBar`, so this is the de facto word.
- Update the STAGING children's strings rather than adding a parallel set.

### 3. Relocate the AI claim to where the AI actually runs

**Diagnosis (verified 2026-09-13):** "AI" appears in exactly ONE parent-facing place, the mode name,
and that is the one step in the pipeline with no AI in it. This is why users report the app "has no
AI" while the code is full of it.

| Step | Real AI | Says today | Should say |
|---|---|---|---|
| Framing export | `AIVideoUpscaler` (Real-ESRGAN), every export | "Rendering" | **"Enhancing video"** |
| Spotlight | YOLO player detection, T4 GPU | nothing | **"Finding players"** |
| Manual framing | none | "AI Focus" | **"Framing"** |

**Name the step, never promise the outcome.** "Enhancing video" is true and checkable.
"Enhanced to HD" is a quality claim, and **T9970 has not measured whether it holds** - do not ship
any sharpness, resolution or quality promise until it has. Fixing a credibility problem with a second
unverified promise would put us back where we started.

### 4. Status labels: presentation only

**T8470's Draft/Shared model stands** (2026-09-10 override UPHELD). Source N11 is taken as
presentation, not as a new state machine. `draftStage.js` stays the single source and T9600 keeps
its job. Each existing state gains a plain-language second half:

| State (unchanged) | Label | What it tells a parent |
|---|---|---|
| Draft | `Draft / Not exported yet` | There is no video to watch yet. |
| Ready | `Private / Ready to watch` | A video exists, only you can see it. |
| Shared | `Shared / Anyone with the link` | Names the audience before they wonder. |

Coordinate with **T9900**, which owns the real per-object status plumbing. The two must agree on one
status vocabulary.

### 5. Every stage states its point

**The rule: every stage states its point in one sentence, and no explanation may use the feature's
own name as the reason for the feature.**

The current framing copy fails this test. "So you can focus the clip around your player" restates the
feature in the feature's own words, so a parent who did not already know why ends up no wiser. Every
other screen has the same gap: `FramingInstructions.jsx` gives three mechanically perfect steps
(move the box, step forward, move it again) and never says why bother.

| Screen | The missing half |
|---|---|
| Mark play | You are bookmarking, not editing. Tap through the whole game first and edit later. |
| Framing | You filmed wide from the stands, and you are sending a phone-shaped video. Framing is you choosing what survives the crop. |
| Spotlight | Twenty-two kids in the same kit. This is how anyone watching knows which one is yours. |
| Publish | Nobody can see this until you publish it. |

Spotlight's line is the strongest sentence in the product and is currently written as a definition
(`SPOTLIGHT_CAPTION`) rather than a reason. **Spotlight stays optional but encouraged** (user
decision 2026-09-13) - the copy should make the case without gating anything on it. T9960 owns the
flow placement; this task owns the words.

The framing answer is checkable, not marketing: output aspect is selectable 9:16 or 16:9 via
`AspectRatioSelector`, so a wide source genuinely has to lose something.

## Acceptance criteria

- [ ] No surface carries the modifier while a sibling surface does not; `SECTION_NAMES.HIGHLIGHTS`
      no longer declares one word and holds another.
- [ ] "AI Focus" is gone; **Framing** is the mode noun everywhere including accessible names,
      tooltips, toasts and fullscreen.
- [ ] "AI" appears only where AI runs, and no quality outcome is promised anywhere.
- [ ] Every stage has a one-sentence reason that does not use the feature's own name.
- [ ] Draft/Shared unchanged in `draftStage.js`; only presentation gained a second half.
- [ ] Tests asserting old copy are **updated**, not deleted or worked around.
- [ ] **Single cutover.** A half-done rename is what produced the mixed vocabulary in the first
      place. If it cannot land whole, it does not start.
