- **Root cause (the 699px symptom was TWO independent bugs, no shared wrapper):**
  - *Bug A — parked settings drawer overflow (Overlay + Focus, every width <1024px).*
    `SettingsRail`'s mobile drawer stays mounted when closed, translated
    `translateX(316px)` off-canvas (`SettingsRail.jsx:101,106`). Nothing clipped
    it, so it grew a horizontal scrollbar on the app's inner `flex-1 overflow-auto`
    pane (`App.jsx:984`; the shell itself is `h-dvh overflow-hidden`, so the leak
    was on the INNER pane, never the document). Overlay's stage row was `relative`
    but not clipping; **Focus's stage row was missing `relative` entirely** despite
    a code comment (`FocusModeView.jsx` ~766) claiming it was the drawer's
    containing block — so the drawer + its `absolute inset-0` scrim resolved against
    the document root.
  - *Bug B — fixed 352px plays panel with no collapse at 640-1023px (Annotate).*
    `ClipsSidePanel` mounted via a raw `hidden sm:flex` (640px) CSS gate while every
    JS decision uses `useIsMobile()` (`max-width:1023px`). In the 640-1023px gap the
    panel was permanently visible, permanently 352px, with the only dismiss toggle
    gated `flex sm:hidden` (i.e. it existed only <640px). At 699px this squeezed the
    canvas to ~250px. The panel was also not `shrink-0`, so its `flex-1` sibling
    absorbed 100% of the squeeze.
