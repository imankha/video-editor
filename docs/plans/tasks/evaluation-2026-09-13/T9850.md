## Outcome record

- **Root cause (structural, not copy — confirmed by grep before changing anything):** quest_1's last
  step `playback_annotations` was gated SOLELY on the `played_annotations` achievement
  (`src/backend/app/routers/quests.py` `_check_all_steps`), which fires ONLY when the user enters
  Preview-plays mode inside Annotate (`modes/annotate/hooks/useAnnotationPlayback.js:284`). A user who
  saved a clip and navigated to Focus/Spotlight/Library was pinned at "4/5" while the guide told them
  to click **Preview plays** — a control that exists only on the Annotate screen. This is exactly
  observation B05·R4 ("guidance stayed at 4/5 in framing, Spotlight and the library, pointing to
  unavailable Preview plays"). The persistent-next-action UI the brief proposed (Frame this clip /
  Keep marking plays) was ALREADY shipped by T9580, so the real, minimal scope was the guide's own
  completion PREDICATE and DESCRIPTION, not a new UI component.
- **Fix (OR-satisfy, the lower-risk option the brief prefers):**
  - `routers/quests.py` `_check_all_steps`: `steps["playback_annotations"] = 'played_annotations' in
    achieved or rc["reels"] >= 1`. `rc["reels"]` is the own-auto-project-clip count
    (`raw_clips.auto_project_id IS NOT NULL AND shared_by IS NULL`) that `annotate_brilliant`/`rate_clip`
    already use — reused rather than inventing a new "has a saved result" signal. Preview plays stays a
    sufficient path (no existing completion regresses). Because `_check_all_steps` is the single choke
    point `/progress` and `/claim-reward` both derive from, the displayed and claimable state can never
    disagree — the T9410 invariant holds and adding an OR only makes completion easier.
  - `config/questDefinitions.jsx`: the `playback_annotations` DESCRIPTION no longer instructs a required
    Preview-plays click; it points at the persistent T9580 next actions (`ANNOTATE.FRAME_THIS_CLIP` /
    `ANNOTATE.KEEP_MARKING_PLAYS`). Removed the now-unused `Play` lucide import.
  - Verified no OTHER quest_1 step hard-requires rating/tagging/source-preview as its only path:
    `rate_clip` is already `'clip_rated' in achieved OR rc["reels"] >= 1`, so creating an editable clip
    completes it without a rating gesture. No change needed there (brief: fix only if you find one).
  - Left deliberately unchanged: the step TITLE (`ANNOTATE.PREVIEW_PLAYS`) — T9860 owns final
    vocabulary and the FE/BE STEP_TITLES sync test must keep passing; and `data/questDefinitions.js` —
    it carries only `step_ids` (not completion), and OR-satisfy keeps the id, so no FE-shape change.
