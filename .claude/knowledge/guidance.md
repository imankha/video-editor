# Guidance (coach pulses and guide sentences)

The coach says ONE sentence per screen state and pulses the ONE control that sentence names.
Epic F (T12730-T12770) made that a single path.

## Entry points
- `src/frontend/src/components/instructions/resolveGuide.js`: `GUIDE_RULES` (first match wins per `screen`), `resolveGuide(facts)`, `GUIDE_STATES` fixtures, `resolvePickGuide` (Overlay pick channel), `homeFacts`.
- `components/instructions/guideTargets.js`: `GUIDE_PULSE` names (value = the control's testid where it has one) and `GUIDE_PULSE_CLASS`, the ONLY place the string `coach-target-pulse` lives besides `index.css`.
- `components/instructions/GuideScope.jsx`: `<GuideScope guides={[guide, ...]}>` and `useGuidePulse(target|[targets], {suppress})`.
- Sentences: `GUIDE.*` in `config/displayNames.js`.

## Invariants
1. **Every rule has `pulse` (a GUIDE_PULSE value, or an array when the sentence names two controls, e.g. Annotate watch = Play + Mark play) XOR `noPulse` (reason string).** Enforced by `instructions/guideRules.pulse.test.js`, which also requires each named target to have a consumer outside `instructions/`.
2. **Guidance on/off is decided once**, in `GuideScope` (`useGuidanceSettings().coachEnabled`). Controls never read the setting. Outside a scope nothing pulses; innermost scope wins (a modal does not inherit the screen's pulse).
3. **A control opts in with `useGuidePulse(GUIDE_PULSE.X)`** (or the `guideTarget` prop on Button, ActionCard, PrimaryCta, CtaBar actions, ClipListItem, DraftTile, ReelTile). Pass `suppress` while it is busy, disabled, dragging, or fullscreen.
4. **No hand-wired pulse.** `instructions/guidePulse.guard.test.js` reads raw source: the pulse class only in `guideTargets.js` + `index.css`; the old prop names (`pulsePlay`, `pulsePreview`, `pulseGenerate`, `pulseUpload`, `pulsePortrait`, `guidePulse`, `homePulse`, `pickPulse`) and `data-trim-guide` / `trim-guide-pulse` absent from non-test source. Local variables holding the hook result are named `pulseClass`.
5. **Reduced motion** is ONE rule in `index.css`: `.coach-target-pulse` drops the animation and gets a 2px amber `outline` (not box-shadow: several targets set an inline box-shadow). Never add per-site `ring-*` / `motion-reduce:` classes for a pulse.
6. Pure render output: nothing here is stored or persisted.

7. **Got it vs end cards (2026-10-17).** Every card has Got it (floating: acknowledges the rule id in `guideFocusStore`; inline: hides for that mount only) EXCEPT `end: true` rules (nothing follows in the current state: `home.games.all-done`, `finished.done`), which show only X (turn guidance off) and ignore Esc, so finishing the walk nudges users to switch guidance off. `modalRule(..., { ownGotIt: true })` drops the card's Got it when the dialog's own button already says Got it. Only shaded (focusable) cards grab keyboard focus; progress/error/inline cards never do.
8. **Home review state** comes from `reviewCounts(games)`: a game is reviewed once `viewed_duration` (the furthest-playhead high-water mark) is at least `REVIEWED_FRACTION` (0.9) of `video_duration`. After the first finished highlight, a started-but-unreviewed game gives `home.games.keep-reviewing`; all reviewed + zero drafts gives the `home.games.all-done` congrats end card. Before any finished highlight the plays rules still steer to making one. keep-reviewing sends the user back into Annotate, so the `annotate.has-plays.*` rules ("Keep going") keep the player (`ANNOTATE_PLAYER`: video + transport) clear like the watch rule; before that, Play sat under the shade and the card covered the transport.
   **Expired games are invisible to the coach (2026-10-17):** `reviewableGames(games)` (drops `storage_status === 'expired'`) feeds `reviewCounts`, the `games`/`gamesWithPlays` facts, and the FIRST_GAME pulse target in `ProjectManager`. An all-expired list reads as "no games" (upload guidance); the coach never says "open your game" about one.

   **Uploading games never steer toward a highlight (2026-10-17):** a game whose upload hasn't finished has no source in storage (backend `storage_status: 'uploading'`, clip seams 409 `source_uploading`). `useIsGameUploading(gameId)` (uploadStore, primitive boolean) feeds Annotate's `uploading` fact: `annotate.uploading.selected` (noPulse) and `annotate.uploading.has-plays` (pulses Mark play) outrank every highlight rule; the orientation slots are `locked`, the 5-star choice card is skipped (`offersHighlightChoice`), and the header hides Frame/Spotlight. Home's `drafts` fact excludes drafts waiting on an upload and `DraftTile` suppresses its pulse. Residual: the gate is the in-tab upload store only. A pending game opened with NO store entry (reload before Resume, other tab/device, dismissed failed upload) is ungated, and Focus then gets 409 `source_uploading`, which FocusScreen renders as a blank player. Home can't open pending games (`readyGames`), so only a direct link reaches that. Don't gate on `/load`'s `storage_status === 'uploading'` without a lift path: it would stay locked after an in-tab upload completes.

9. **Shade escapes (2026-10-17).** `SHADE_ALWAYS_CLEAR` = the Guidance switch AND the editor Home/Back (`data-testid="editor-home"` in `UnifiedHeader`): leaving a screen is never blocked by a Focused step. When the anchor is off-screen/unmeasurable the fallback shade (pointer-events none) still cuts out every ON-SCREEN keepClear/shadeClear/pulsing/always-clear rect; it is hole-less only when none of those is visible. Overlay's pick walk (`pickWalkPhase` in `OverlayModeView`) is null while the spotlight export is `processing`/`finishing`, so only the job card speaks.

10. **Dialog cards sit beside the dialog; the Guidance switch is above every modal (2026-10-17).** `<Guide inline beside>` (`BesideGuide.jsx`, used by the Upload game modal; the dialog panel carries `data-guide-panel`) portals the card to the right (else left) of the panel, level with the guide's anchor (`placeBeside`, `BESIDE_CARD_WIDTH` 336), so it never sits on or inside the control it names. No room (a phone) or nothing measurable (jsdom) renders it inline in place, as before. The other dialogs still use the plain inline card at the top of their body. `GuidanceToggle` keeps an invisible same-size slot in the header/cluster and draws the real switch (`guidance-toggle`) in a body-level `fixed` layer (`Z.TOAST`) pinned over that slot, because no header can out-stack a fixed modal backdrop. Anything that must measure the switch still finds it by testid. The layer re-reads the slot rect EVERY animation frame (T13460; resize/scroll/ResizeObserver missed siblings mounting or banners clearing, leaving the pill over the logo/icons); `setBox` bails when unmoved. `expectSwitchClear` in `guide-no-overlap.spec.js` asserts it overlaps nothing in the top 120px.

11. **Player-layer guides are shaded, card beside the primary CTA (2026-10-18).** The Focus/Overlay ready panels and the Finished viewer live in `CollectionPlayer` (a `role="dialog"` layer), and used to render `<Guide inline>`: a full-width unshaded bar. They now use the floating `<Guide>`: `layerIsOpen(anchor)` in `FloatingCoach` ignores a layer that CONTAINS the guide's anchor (that layer is the guide's screen); any other open layer (a modal on top) still blocks it. The rules (`readyPanel()` in `resolveGuide.js`, `finished.*`) anchor on the primary card, `keepClear` every CTA, `shadeClear` the `collection-player-video` (a preference, so on a phone the card covers part of the picture rather than a CTA), and set `side: 'beside'`: `placeCoach` tries left then right of the anchor, and `clearOfPulses({ floatFirst })` takes the nearest floating slot before the full-width strips. Every way out stays bright: `SHADE_ALWAYS_CLEAR` includes the player's `player-close` and `player-back-to-game`. A focused coach button keeps Space/Enter/arrows from the player's window shortcuts (capture listener stops them when the target is inside `floating-coach-host`). Got it on these cards acknowledges the rule id like every floating card (invariant 7), so it stays dismissed for later highlights until guidance is toggled back on. Live-checked at 2000x1170 (left of Finish), 1280x800 (above-left, no room beside) and 390x844 (above Finish, over the video).

## Landmines
- **Trim `phase`.** The two trim rules have `step: null` and name their own `phase` (`'split'`/`'adjust'`) because `data-phase` and the coach re-measure key read it. `SegmentLayer` pulses its track (`TRIM_TRACK`) and speed/trash buttons (`TRIM_ADJUST`) through the hook.
- **Overlay has two channels**: `OverlayModeView` scopes `[overlayJobGuide, pickGuide]` (job state + pick sequence), so two targets can be active at once. Exception (T13380): while the job channel resolves `overlay.text` (Add text tapped) the scope is `[overlayJobGuide]` only, so the pick walk's Generate pulse stands down; `overlay.text` cuts the on-video input and timeline text blocks out via `keepClear` and the sheet via `shadeClear`.
- **Overlay with no detection markers** (T12790): `useGuidedAthletePick` reports phase `'none'` once regions have loaded (`canPark`) and `SpotlightPickGuide` shows `overlay.pick.none` (drag the circle). Before that, `total === 0` meant phase null and Overlay opened with no guide.
- **Annotate holds its guide until a game id exists AND the initial position has landed** (`holdGuide = !isGameDataReady || (isInitialPositionPending && !videoError)`; expired games never arm the pending step, a failed video never holds). Without the second half the guide showed "You've marked N plays" while the video loaded, then switched to the resumed play's message (see annotate.md "Initial position is ONE step"). Reopening an uploading game must restore the id from the upload store (T12790: the blob-restore effect used to reset it to null, so no guide for the whole upload).
- **Landscape cockpit** (`FocusCockpit`) resolves `focus.cockpit.*` (see Full-bleed editors) and provides its own `GuideScope`. `CropOverlay` no longer has a "0 focus points" fallback: unscoped means no pulse. `guided` on CropOverlay only means "the sentence is shown elsewhere, so no chip".
- A new `GUIDE_PULSE` key needs a consumer, a rule, and a row in `resolveGuide.pulseTargets.test.js`.
- **Dialogs** (T12790): `screen: 'modal'` rules built by `modalRule(id, name, title, {when, pulse|noPulse})`; facts are `{ screen: 'modal', local: { modal: '<name>', ...state } }`. Each dialog wraps itself in `GuideScope` and renders `<Guide inline testId="modal-guide">` at the top of its body (the floating coach hides behind any open dialog). A new dialog = a rule + `GUIDE.modal` copy + the inline mount.
- **The Finished viewer (`DraftReelPreview`) is a fullscreen overlay mounted as a SIBLING of Home (`ProjectsScreen`/`ProjectManager`) in App.jsx, not nested inside it** (T12800). `GuideScope`'s "innermost wins" is plain React context, so it only resolves ancestor-vs-descendant; a sibling overlay never shadows Home's own scope. `ProjectManager`'s `homeGuide` now goes `null` (same as while the upload modal owns the guide) whenever `useReelPreviewStore`'s `payload` is set, so Home's pulse stands down instead of staying CSS-active, invisibly, behind the opaque viewer. Any other App.jsx-level sibling overlay over Home needs the same null-gate -- `GuideScope` nesting alone won't catch it.
- **Full-bleed editors** (T12790): the landscape cockpit and Focus fullscreen draw the same resolved guide with `CompactGuide` (slim strip, pointer-events pass through, Turn off guidance only). The cockpit walks drag, Preview (`COCKPIT_PREVIEW`), Generate; fullscreen sends the user out (`focus.fullscreen.leave`, pulses `EXIT_FULLSCREEN`) once the stage steps are done.
- **Focus video load failure** outranks job state (`focus.video-error[.retry]`); Home's Games tab has `home.games.error` (Retry), and only the Games tab waits on the games fetch.
- **The card never covers a pulsing control or a keepClear rect, and every pulsing control is cut out of the shade** (`clearOfPulses` in `placement.js`; FloatingCoach reads `.GUIDE_PULSE_CLASS` rects). Staging 2026-10-14: the editor's dock-collides-with-avoid fallback (`anchor.top + 8`) put the card on Done. T12800: when its 4 fixed candidates (dock, above-anchor, top strip, `next`) are ALL blocked, `clearOfPulses` now scans the viewport (full-width strips everywhere; floating `{left,top}` spots too on non-phone widths) for the nearest clear slot, closest-to-anchor wins, before giving up and returning `next` -- the Clips tab at 1280/1579 wide and the editor's "Mark play" strip at 1579 wide both had every fixed candidate blocked.
- **`keepClear` vs `shadeClear`.** `keepClear` is cut out of the shade AND kept off by card placement and the overlap oracle. `shadeClear` is cut out of the shade ONLY; placement and `data-guide-overlap` ignore it, so the card may sit over it. Use it for a target that fills most of the screen: the Annotate play editor's video (`annotate.editor`, `[data-testid="annotate-coach-stage"]:not([data-full-bleed-video]) video`) was in `keepClear` first, left no card slot, and the card landed on Done (`guide-no-overlap` failed at 390/768/1579). Both lists are comma-joined into a key in `FloatingCoach`, so no selector in either may contain a comma. `AnnotateModeView` sets `data-full-bleed-video` on the stage in mobile fullscreen (video is `absolute inset-0`), so the `:not()` selector matches nothing there and the shade dims the video on phones. Plumbed `annotate()` -> `resolveGuide` -> `Guide` -> `FloatingCoach`; `SpotlightPickGuide` calls `FloatingCoach` directly and has none. Pinned by `resolveGuide.keepClear.test.js` C4. Placement treats `shadeClear` as a PREFERENCE: `FloatingCoach` first looks for a slot clear of it too, and only if none exists falls back to clearing just the hard targets (never onto Done). On a phone that slot is the strip below Done, which only fits because the editor rule sets `compact: true` (text-sm, tighter padding; `annotate()` -> `resolveGuide` -> `Guide` -> `InstructionCoach`); a longer sentence or a shorter phone makes the card cover the video again.
- **The modal shade is a GUARANTEE while a guide is focusable, never best-effort** (T12800). `focusable && !layerOpen` renders a shade even when the anchor's `rect` can't be measured OR it's offscreen -- `[]` holes, i.e. a full, hole-less shade, rather than skipping it. **It is ALWAYS `pointer-events: none`** (`data-scrolls-through="true"`): a full shade that CAPTURED pointer events would either block the wheel/touch scroll an offscreen target's hint asks for, or (found live, staging 2026-10-15) capture clicks across the WHOLE page on an ordinary, momentarily-unsettled on-screen measurement, reading as a frozen page -- only the normal, precisely-measured cutout may ever capture pointer events. The scroll-hint pill's z-index matches the shade's (not one below) since the two can render together. A docked card is ALSO capped to the floating card's width (`w-[min(calc(100vw-24px),26rem)]`), centred -- it used to span edge-to-edge (`inset-x-3 w-auto`), reading as a near-full-width bar for a one-line message on desktop.
- **Three `display:contents` anchor landmines, all closed by T12800, all hit by `annotate-highlight-slots`** (`HighlightOrientationSlots` renders `className="contents"` TWO levels deep when `inline`, and its real boxes -- Portrait + Landscape -- are SIBLING grid items of a shared `grid` parent once `contents` drops out of layout):
  1. `anchorRect`'s "measure the union of children" fallback only looked at DIRECT children, so the zero-rect INNER contents wrapper got filtered out, the union came back empty, and the shade silently never rendered. Now recurses into any child that is ALSO `display:contents`.
  2. A ResizeObserver attached to the anchor directly never fires as its real children resize (the anchor's own border box is permanently 0x0), so a stale measurement from an early/unsettled render could never self-correct. The observer now watches the real, box-having descendant(s) (`realBoxes`, the same recursive descent as `anchorRect`).
  3. **The actual bug behind a "Scroll down to continue" stuck over a fully on-screen step, found by live instrumentation**: `coveredByPage`'s containment check (`anchor.contains(top)`) only checked ONE direction. The two cards' union rect's CENTRE falls in the grid GAP between them (no card's own box covers that exact pixel), so `elementFromPoint` there returns the shared grid PARENT -- an ANCESTOR of the anchor, not something covering it. Without `top.contains(anchor)` too, that parent read as "covering" the anchor, permanently (nothing about a static screen's measurement ever changes to retrigger the check). Fixed with `top.contains(anchor)` added to the guard.
  Any FUTURE guide anchor that is a `display:contents` wrapper around multiple SIBLING children should expect all three to matter, not just the first one found.
- **Transient corner cards (T13030).** `FocusCompletionRecovery` (the "Highlight ready" View/Dismiss card) auto-clears after 8s WITHOUT acknowledging the job (still recoverable on reload) and carries `data-guide-transient`; `coveredByPage` in `FloatingCoach` ignores a hit-test landing on such an element, so it can't raise "Scroll down to continue" over a visible anchor. The card is not repositioned away from the action band: its overlap is bounded by the 8s lifetime. Mark any future short-lived overlay the same way.
- Scopes must sit above the control: hooks in a component rendered outside its screen's `GuideScope` silently never pulse (the fail-visible default).
- e2e: `e2e/T12730-guide-pulse.spec.js` asserts `.coach-target-pulse` per screen; tests may assert the class name, source may not.
- **Overlap oracle (T12800).** After the final position is chosen, `FloatingCoach` names every pulsing/keepClear rect the card still covers in `data-guide-overlap="<testids>"` on `floating-coach-host` (absent = clear) and `console.warn('[guide-overlap]', ruleId, covered)` once per rule+placement. The viewport scan (above) means this now only fires when literally nothing on screen is clear. `FloatingCoach.overlap.test.jsx` (jsdom) pins it, including a full-column-of-pulses case that forces the scan itself to find nothing. `e2e/guide-no-overlap.spec.js` sweeps 390/768/1280/1579 wide plus the 844x390 landscape cockpit: Home tabs (empty + the dev-fixture account), Upload modal, Annotate watch/playing/editor/choice/has-plays/selected, Focus drag/play/keep/preview/generate, the cockpit, the Finished viewer, and the Buy-credits/Edit-game dialogs. Its header lists every state NOT reached and why (Overlay's pick walk only runs when the fixture account has a streamable In-Spotlight draft with detections -- it `test.skip`s loudly otherwise; trim, job/error states, Overlay text and the share modal aren't driven). Branch CI does not run it -- run it locally after any placement/rule-data change and record the output.
- **Guidance is a profile-persisted setting, not per-session** (T12800 landmine). A prior run (or a live user) can leave it ON for the shared dev-fixture account, and Home's shade then blocks whatever the CURRENT rule doesn't cut out, including a NEW spec's own setup clicks -- hung a test for its full 240s budget, reported at an unrelated later line (the finally block's cleanup) because that's whatever was in flight when the test's overall timeout fired. Any spec that clicks through Home before its own `setGuidance(true)` must force it to a known OFF state first (`e2e/guide-no-overlap.spec.js`'s Focus/Overlay tests).
- **Rule-table check (T12800).** `guideRules.namedControls.test.js`: every "tap/drag/pick/open X" in a rule's sentence maps (explicit `CONTROL_PHRASES` table) to the rule's `pulse` or `keepClear`, or has a reason in `NAMES_OFFSCREEN`; a new sentence with an action verb and no table row fails. noPulse rules are documented by their noPulse reason.
- **Review plays keeps the video unshaded (T13100, T13180).** `annotate.review` sets `shadeClear: [annotate-review-video]` (shade-only, so the card may still sit over it); the named tile (Share plays) keeps its pulse cutout. Pinned by `AnnotateModeView.reviewShade.test.jsx`, which mounts the real review layout: a rule-data test with a fixture carrying the testid cannot catch this.
- **A failed game upload outranks the watch/plays/review rules (T13390).** `annotate.upload-failed` anchors on, keepClears, and pulses Retry upload on `upload-preview-notice` (`UploadPreviewNotice` renders first inside BOTH AnnotateModeView scopes). - **Players opened from Home sit under the fixed Guidance switch (T13190).** `CollectionPlayer`'s `clearGuidanceToggle` prop pads its header (`pt-16`) and wraps the title/buttons so the switch never covers Share/Download/Close; `DraftReelPreview` and `PublishedReelsPanel`'s `IntroStoryPlayer` pass it.
- **Card places against the pulsing control (T13060).** `FloatingCoach` passes `visibleRects('.coach-target-pulse')[0] ?? anchorRect` to `placeCoach`/`dockPlacement`/`clearOfPulses`; the rule's anchor stays the shade/scroll anchor. A big anchor (Focus stage, Home heading) used to park the card at its centre/top, hundreds of px from the tile or Play. Pinned by `FloatingCoach.nearPulse.test.jsx`.
